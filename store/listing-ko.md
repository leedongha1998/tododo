# Play 스토어 등록 문구 (한국어)

Play Console → 기본 스토어 등록정보에 그대로 붙여넣는 초안. 글자 수는 Play 기준(공백 포함)이다.

---

## 앱 이름 (최대 30자)

```
투두두두 - 친구와 겨루는 투두
```

18자. 이름만 쓰고 싶으면 `투두두두`(4자)도 가능하지만, 검색에서 "투두"·"친구"가 잡히도록
부제를 붙여두는 편이 낫다.

---

## 짧은 설명 (최대 80자)

```
같은 할 일을 걸고 친구와 대결하세요. 증거를 올리고 서로 승인해야 승부가 납니다.
```

44자. 스토어 목록과 검색 결과에 이 문장만 보이므로 "할 일 + 대결"이 한 줄에 다 들어가야 한다.

### 대안

```
혼자 하면 미루게 되니까. 같은 할 일을 건 대결로 오늘 하나는 끝내세요.
```

---

## 자세한 설명 (최대 4000자)

```
할 일 목록은 늘 길어지기만 하고, 오늘도 하나도 못 지웠나요?
투두두두는 같은 할 일을 친구와 걸고 겨루는 투두리스트입니다. 미루던 일이 겨루는 순간 오늘 할 일이 됩니다.

■ 이렇게 씁니다

1. 대결할 내용을 정해 모집을 올립니다. "아침 7시 기상", "방 청소하기"처럼 무엇이든 좋습니다.
2. 누구든 먼저 참가하는 사람과 자동으로 매칭됩니다. 상대를 따로 찾아 초대하지 않아도 됩니다.
3. 각자 할 일을 끝내고 증거를 올립니다.
4. 서로의 증거를 확인하고 승인하면 승부가 확정됩니다.

■ 두 가지 대결

속도전 - 누가 먼저 끝내느냐로 겨룹니다. 사진이나 글로 증거를 남기고, 둘 다 승인받으면 먼저 제출한 쪽이 이깁니다.

품질전 - 얼마나 제대로 했느냐로 겨룹니다. 사진 증거가 필수이고, 둘 다 승인하면 함께 완주한 것으로 끝납니다. 속도를 다투지 않으니 승패를 가르지 않습니다.

■ 판정은 서로가 합니다

완료 버튼만 누르면 되는 앱이 아닙니다. 증거를 올려야 완료를 주장할 수 있고, 상대가 그 증거를 승인해야 인정됩니다. 납득이 가지 않으면 이의제기할 수 있고, 이의제기를 받은 완료는 무효가 됩니다. 양쪽 다 이의를 제기하면 승자 없이 미결로 남습니다.

증거를 다시 올려 다시 판정받을 수도 있습니다. 다만 속도전에서는 마지막으로 제출한 시각이 기준이 되므로, 다시 올릴수록 승부에서 불리해집니다.

■ 혼자 쓰는 할 일 목록도 있습니다

대결과 별개로 개인 할 일을 적고 지울 수 있습니다. 대결로 걸 만한 일이 없는 날에도 평범한 투두 앱으로 씁니다.

■ 전적이 남습니다

끝난 대결은 프로필에 전적으로 쌓입니다. 속도전은 몇 승 몇 패인지, 품질전은 몇 번 함께 완주했는지 볼 수 있습니다.

■ 이런 분께

- 계획은 잘 세우는데 실행에서 매번 미끄러지는 분
- 혼자 하는 습관 앱은 며칠 만에 접게 되는 분
- 친구와 가볍게 겨루면서 하루 하나는 끝내고 싶은 분

■ 이용 안내

- Google 계정으로 로그인해 사용합니다.
- 대결 상대에게는 표시 이름과 제출한 증거가 보입니다. 증거 사진에 원치 않는 정보가 담기지 않았는지 확인하고 올려주세요.
- 계정과 데이터는 앱 안에서 언제든 삭제할 수 있습니다. 프로필 화면의 계정 삭제를 눌러주세요.
```

약 1,050자. 4000자 한도에 여유가 크므로, 기능이 늘면 문단을 덧붙이면 된다.

> **주의**: 스토어 문구에 없는 기능을 적으면 심사에서 걸린다. AI 심판, 푸시 알림, 그룹 대결, 랭킹은
> 아직 없으므로 위 문구에 넣지 않았다. 기능이 추가되면 이 파일과 스토어 문구를 같이 갱신할 것.

## 카테고리 / 태그

- **앱 카테고리**: 생산성 (Productivity)
- **태그**: 할 일 목록, 습관, 자기계발
- 게임 카테고리로 등록하지 않는다. 대결이라는 표현이 있어도 기능은 생산성 앱이다.

## 콘텐츠 등급 설문 답안

Play Console → 앱 콘텐츠 → 콘텐츠 등급에서 아래대로 답한다. 실제와 다르게 답하면 등급이 무효가 된다.

| 질문 | 답 |
| --- | --- |
| 폭력, 성적 콘텐츠, 비속어, 약물 | 모두 아니오 |
| 도박, 실제 도박 요소 | 아니오 (대결에 금전이 걸리지 않는다) |
| 앱 내 구매 / 디지털 구매 | 아니오 |
| 위치 정보 공유 | 아니오 |
| 광고 표시 | 아니오 |
| **사용자가 만든 콘텐츠를 다른 사용자와 공유하는가** | **예** — 대결 상대에게 사진·텍스트 증거가 보인다 |
| 사용자 간 소통(채팅/메시지) | 아니오 (자유 대화 기능은 없다) |

## 스크린샷 (`store/screenshots/`, 준비 완료)

에뮬레이터(Pixel 6, 1080×1920)에서 **실제 앱**으로 찍었다. 업로드 순서는 파일명 순서다.

| 파일 | 화면 | 보여주는 것 |
| --- | --- | --- |
| `01-home.png` | 홈 | 위쪽 내 대결(판정중/종료) + 아래쪽 개인 할 일. 앱 정체성이 한 장에 들어간다 |
| `02-recruits.png` | 모집함 | 남이 올린 모집과 참가하기 버튼 — "먼저 참가하는 사람과 매칭" |
| `03-battle.png` | 대결 진행 | 내 증거 / 상대 증거 / 승인·이의제기. 이 앱의 핵심 규칙 |
| `04-profile.png` | 프로필 | 속도전 승패, 품질전 완주 기록, 계정 삭제 경로 |

찍을 때 한 것:
- DEBUG 배너가 없는 **profile 빌드**로 설치 (`flutter build apk --profile --dart-define-from-file=env.json`)
- 상태바 정리: 데모 모드로 시계 9:00 고정, 알림 숨김, 배터리 100%
  (`adb shell am broadcast -a com.android.systemui.demo -e command enter` 이하)
- 해상도 1080×1920(9:16)로 고정 — 기본 1080×2400은 2.22:1이라 Play가 거부할 수 있다
  (`adb shell wm size 1080x1920`, 끝나면 `wm size reset`)
- 샘플 데이터는 `tool/screenshot_seed.sql`로 넣고 **`tool/screenshot_cleanup.sql`로 전부 지웠다**

다시 찍어야 하면 같은 순서로 하면 된다. 화면에 표시되는 이름(`Dongha Lee`)을 바꾸고 싶으면
`profiles.display_name`을 잠시 바꾼 뒤 찍고 되돌린다.

규격: PNG 또는 JPEG, 한 변 320px 이상 3840px 이하, 파일당 8MB 이하. 현재 파일은 전부 1080×1920, 100KB 안팎.

## ⚠ 심사 리스크: 사용자 생성 콘텐츠(UGC) 정책

Play의 UGC 정책은 **사용자끼리 콘텐츠를 주고받는 앱**에 신고 수단과 차단 수단을 요구한다.
이 앱은 모집 방식이라 모르는 사람과도 매칭되고, 그 상대가 올린 **사진을 보게 된다**.
지금은 신고도 차단도 없어 심사에서 지적받을 수 있다.

최소 대응(구현 필요 여부는 스코프 판단):

- 신고한 상대와 다시 매칭되지 않게 하는 **차단**
- 정책 문서와 스토어 설명에 신고 경로 명시
