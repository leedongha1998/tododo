마이그레이션이 **파일만** 만들어진 변경(이 저장소는 로컬 Docker가 없어 원격 적용이 늘 오너 승인 사안이다)은
리뷰에서 **그 컬럼을 쓰는 Dart 호출이 "값이 없을 때도 키를 보내는가"**를 반드시 확인한다. PostgREST는 본문에
있는 키를 스키마 캐시에서 찾으므로, `{'due_at': dueAt?.toUtc().toIso8601String()}`처럼 null도 키로 들어가면
**기한을 안 쓰는 사용자의 추가·수정까지 전부 400(PGRST204)으로 죽는다.** 읽기는 `select()`가 전체 컬럼이고
`fromMap`이 없는 키를 null로 받으므로 멀쩡해서, "읽히는데 저장만 안 된다"로 증상이 나온다.

**Why:** 2026-11-09 todo-due-date P0 리뷰에서 plan.md가 이 상황을 "앱이 **기한을 보내면** 서버가 거부한다"로
적어 두었는데 실제 코드는 기한이 null일 때도 키를 보냈다 — 그 문장을 믿고 커밋·배포 순서를 정하면 투두 쓰기
전체가 죽는 판을 "일부 기능만 영향"으로 과소평가하게 된다.

**How to apply:** `supabase/migrations/`에 새 파일이 있고 "원격 적용은 뒤에"라고 적힌 변경이면 적용한다.
리뷰 보고에 (1) 영향 범위를 읽기/쓰기로 갈라 적고, (2) "마이그레이션 적용 → 그 뒤 코드 배포"가 선행 조건임을
못 박고, (3) 문서(plan.md 진행 기록)의 서술이 실제 코드와 맞는지 교정 요청까지 넣는다.
