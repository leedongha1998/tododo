떠나기 확인창의 가드 조건은 두 가지로 판단한다.

1. **막는 기준은 "되돌릴 수 없는 자원을 썼는가"다.** 화면이 들고 있는 결과물(증서·응답 객체)의
   존재 여부로 재지 말 것 — 사용자가 입력을 조금 더 고치면 그 결과물이 버려지면서 가드도 같이
   풀리는 구멍이 생긴다. 호출을 보낸 순간 세우고 화면이 사는 동안 내리지 않는 플래그를 쓴다.
2. **오류 상태에서는 막지 않는다.** 화면이 "횟수는 차감되지 않았어요"를 띄우는데 확인창이
   "사용한 횟수는 돌아오지 않아요"라고 물으면 같은 화면이 반대로 말하는 것이 된다.
   되돌아갈 길이 없는 오류 화면을 막으면 지킬 것도 없이 길만 막는다.
3. 공통 가드 위젯으로 묶는 것은 괜찮지만 **제목(사용자가 하던 일)은 화면이 넘긴다** —
   "만들기를 그만둘까요?"가 수정 화면에 뜨면 안 된다. 본문이 양쪽에 다 맞으면 본문만 공용으로 둔다.

**Why:** mobile-ux M7(2026-11-02) 리뷰에서 리뷰어가 probe 테스트로 세 구멍을 다 재현했다.
`_checked != null`로 막은 기준 수정 화면은 재검사(하루 10회 중 1회)를 쓴 뒤 한 글자만 고치면
가드가 풀려 고친 기준과 쓴 1회가 확인창 없이 사라졌다. 내가 plan.md에 적은 근거
("고치기만 한 상태로는 아직 쓴 것이 없다")는 **첫 호출 전에만** 참이었다.

**How to apply:** 유료·한도 자원(AI 호출, 업로드)을 쓰는 화면에 `PopScope`를 붙일 때 적용한다.
가드마다 회귀 테스트를 붙이고(`maybePop`으로만 검증된다 — [[flutter-widget-test-gotchas]] 10번),
"쓴 뒤 더 고친 경우"와 "오류 화면"을 반드시 한 건씩 넣는다.
