# 수동 테스트 시나리오

배포 전 사람이 직접 처음부터 끝까지 돌려보는 시나리오. 유닛 테스트가 덮지 못하는 것
(실제 로그인, 카메라, Storage, 두 사람 사이의 상태 동기화)을 확인하는 게 목적이다.

각 항목은 **절차 → 기대**로 적혀 있다. 기대와 다르면 그 자리에서 멈추고 `TODO_BACKLOG.md`에
한 줄 적거나 바로 고친다.

---

## 0. 준비

### 계정과 기기

- 구글 계정 **2개**가 필요하다. 이 문서에서는 **A**(실기기), **B**(에뮬레이터 또는 두 번째 기기)로 부른다.
- 기기가 하나뿐이면 로그아웃/로그인을 번갈아 해도 되지만, 대결은 양쪽 화면을 번갈아 봐야 해서 훨씬 느리다.
- **카메라 촬영은 실기기에서만 확인된다.** 에뮬레이터 기본 카메라는 셔터가 동작하지 않는다.
  → A는 카메라, B는 갤러리로 사진을 고른다.

### 실행

```bash
flutter run --dart-define-from-file=env.json
```

에뮬레이터를 쓸 경우:

```bash
emulator -avd todododo_avd
```

### 시작 전 확인

- [ ] `flutter analyze` 이슈 0, `flutter test` 전부 통과
- [ ] `supabase migration list`로 local/remote 마이그레이션 목록이 일치
- [ ] Supabase → Authentication → URL Configuration → Redirect URLs에
      `com.todododo.todododo://login-callback/`이 있는지
- [ ] 두 기기 모두 이전 세션이 남아 있지 않은 상태(처음이면 그냥 진행)

### 끝난 뒤

테스트로 만든 대결/투두는 실제 사용자의 `대결 찾기` 목록에 뜨는 쓰레기가 된다. 마지막에 정리한다.
UUID를 미리 정해 넣은 `tool/screenshot_seed.sql`과 달리 이번 데이터는 앱이 만든 것이라
정리 쿼리를 직접 써야 한다(9번 참고).

## 1. 인증과 세션

- [ ] **1-1 최초 로그인** — 앱 실행 → `구글로 로그인` → 브라우저에서 A 계정 선택
      → **기대**: 앱으로 돌아오고 `내 대결` 탭이 열린다. 하단에 탭 네 개(`내 대결`/`대결 찾기`/`할 일`/`프로필`)가
      보이고 `localhost:3000`으로 튕기지 않는다
- [ ] **1-2 세션 유지** — 앱을 완전히 종료(최근 앱에서 스와이프)했다가 다시 실행
      → **기대**: 로그인 화면 없이 바로 `내 대결` 탭
- [ ] **1-3 프로필 표시 이름** — `프로필` 탭 열기
      → **기대**: 구글 계정 이름이 그대로 보인다. `아직 완료된 대결이 없어요.`
- [ ] **1-4 로그아웃** — `프로필` 탭 → 맨 아래 `계정` → `로그아웃`
      → **기대**: 즉시 로그인 화면. 다시 로그인하면 이전 데이터가 그대로 보인다
- [ ] **1-5 계정 분리** — B 기기에서 B 계정으로 로그인
      → **기대**: A가 만든 할 일이 B의 `할 일` 탭에 보이지 않는다

## 2. 개인 투두 CRUD

A 기기에서 진행한다.

- [ ] **2-1 빈 상태** — 할 일이 없을 때 → **기대**: `아직 할 일이 없어요...` 안내
- [ ] **2-2 추가** — `할 일` 탭 → 우하단 `+` → 제목 입력 → 저장 (무엇을 추가할지 고르는 단계는 없어졌다)
      → **기대**: 목록 맨 위(또는 정렬 위치)에 즉시 나타난다
- [ ] **2-3 빈 제목** — `+` → 저장 버튼을 빈 칸으로 누름
      → **기대**: 아무 일도 일어나지 않는다(빈 항목이 생기지 않는다)
- [ ] **2-4 완료 토글** — 체크박스 탭 → **기대**: 제목에 취소선. 다시 탭하면 원래대로
- [ ] **2-5 수정** — 항목 본문 탭 → 제목 바꿔 저장 → **기대**: 목록에 바뀐 제목
- [ ] **2-6 삭제** — 휴지통 아이콘 → **기대**: 목록에서 사라진다
- [ ] **2-7 재시작 후 유지** — 앱 종료 후 재실행 → **기대**: 2-2~2-5의 결과가 그대로
- [ ] **2-8 오프라인 실패 처리** — 비행기 모드 켜고 할 일 추가
      → **기대**: `저장에 실패했습니다...` 스낵바가 뜨고 목록에 가짜 항목이 남지 않는다.
      비행기 모드 해제 후 다시 추가하면 성공

## 3. 대결 모집

- [ ] **3-1 모집 등록** — A: `대결 찾기` 탭 → 우하단 `대결 만들기` → 속도전 선택 → 제목 입력 → `모집 등록하기`
      → **기대**: 화면이 닫히고 `모집을 등록했습니다.` 스낵바
- [ ] **3-2 제목 없이 등록 불가** — 제목이 비면 → **기대**: `모집 등록하기` 버튼이 비활성
- [ ] **3-3 내 모집 목록** — A: `대결 찾기` 탭 열기
      → **기대**: `내가 등록한 모집`에 방금 만든 대결이 있고, `모집 중인 대결`(남의 모집)에는 없다
- [ ] **3-4 남의 모집 보이기** — B: `대결 찾기` 탭 열기
      → **기대**: `모집 중인 대결`에 A의 모집이 등록자 이름·유형과 함께 보인다
- [ ] **3-5 모집 취소** — A: `대결 찾기` 탭에서 아무 모집이나 만들어 `취소`
      → **기대**: `모집을 취소했습니다.` 스낵바 + 목록에서 사라진다. B가 새로고침하면 B 쪽에서도 사라진다
- [ ] **3-6 매칭** — B: A의 모집에서 `참가하기`
      → **기대**: `매칭되어 대결이 시작됐습니다.` 스낵바. B의 `내 대결` 탭에 `상대이름 · 속도전 · 진행중`으로 뜬다.
      A는 `내 대결` 탭을 당겨 새로고침하면 같은 대결이 보인다
- [ ] **3-7 이미 매칭된 모집** — (선택, 계정 3개 필요) 세 번째 계정이 같은 모집에 참가 시도
      → **기대**: `참가에 실패했습니다...` 스낵바. 대결 상대는 먼저 참가한 사람으로 유지

## 4. 속도전 판정 (핵심)

속도전은 결과가 네 갈래다. **대결 4개를 미리 만들어 두고** 하나씩 다른 경로로 끝낸다.
매칭까지는 3-6과 같은 절차이므로 아래에는 매칭 이후만 적는다.

증거를 낸 순서와 승인/이의제기 순서가 결과를 가르므로 **순서를 그대로 지킨다.**

### S1 — 둘 다 승인 (먼저 낸 쪽 승리)

- [ ] A가 먼저 텍스트 증거 제출 → **기대**: `증거를 제출했습니다.` + `상대방의 판정을 기다리는 중이에요.`
      `내 대결` 탭 목록의 상태가 `판정중`으로 바뀐다
- [ ] 이 시점 A 화면 → **기대**: 상대 영역에 `상대방의 증거 제출을 기다리는 중이에요.`
- [ ] B가 텍스트 증거 제출 (A보다 나중)
- [ ] A가 B의 증거를 `승인` → **기대**: `판정을 등록했습니다.` +
      `상대방이 내 증거를 판정하면 결과가 확정돼요.` (아직 안 끝난다)
- [ ] B가 A의 증거를 `승인`
      → **기대**: 대결이 `종료`. A 화면 `승리했습니다! / 먼저 완료를 증명해서 이겼어요.`,
      B 화면 `아쉽지만 패배했어요. / 상대방이 먼저 완료를 증명했어요.`
      양쪽 모두 승인/이의제기 버튼이 사라진다

### S2 — 늦게 낸 쪽이 이의제기로 승리

- [ ] A 먼저 제출 → B 나중에 제출
- [ ] B가 A의 증거를 `이의제기` → **기대**: 확인 다이얼로그에
      `이의제기하면 상대방의 완료가 무효가 돼요. 되돌릴 수 없어요.` → 진행
- [ ] 이 시점 A 화면(새로고침) → **기대**: `상대방이 내 증거에 이의를 제기했어요. 내 완료는 무효로 처리돼요.`
      대결은 아직 `판정중`
- [ ] A가 B의 증거를 `승인`
      → **기대**: B 승리. B 화면 `승리했습니다! / 상대방의 증거가 이의제기로 무효가 되어 이겼어요.`,
      A 화면 `아쉽지만 패배했어요. / 내 증거가 이의제기로 무효가 되어 졌어요.`
      **먼저 냈는데도 졌는지**가 이 케이스의 핵심이다

### S3 — 양쪽 다 이의제기 (미결)

- [ ] A 제출 → B 제출 → 서로 `이의제기`
      → **기대**: 상태 `미결`, 승자 없음.
      양쪽 모두 `양쪽 모두 이의제기를 받아 유효한 완료가 없어요. 승자 없이 미결로 끝났어요.`

### S4 — 재제출로 순서가 뒤집히는지

- [ ] A 제출 → B 제출 (A가 먼저)
- [ ] A가 `증거 다시 제출하기`로 내용을 바꿔 다시 제출
      → **기대**: 제출은 성공하고 상태는 `판정중` 유지
- [ ] 서로 `승인`
      → **기대**: **B 승리**. 재제출로 A의 제출 시각이 B보다 뒤로 밀렸기 때문이다.
      A가 그대로 이기면 버그다

### S5 — 이의제기당한 뒤 재제출

- [ ] A 제출 → B 제출 → B가 A의 증거를 `이의제기`
- [ ] A가 `증거 다시 제출하기`로 다시 제출
      → **기대**: A 화면이 다시 `상대방의 판정을 기다리는 중이에요.`로 돌아가고,
      B 화면에는 A의 증거에 대한 `승인`/`이의제기` 버튼이 **다시** 나타난다
- [ ] B가 이번엔 `승인`, A도 B를 `승인`
      → **기대**: 종료. 재제출로 시각이 밀렸으므로 B 승리

### 속도전 공통 확인

- [ ] **4-a 사진 증거도 가능** — 위 중 한 판은 텍스트 대신 사진으로 제출
      (A는 `카메라로 찍기`, B는 `갤러리에서 고르기`)
      → **기대**: 제출 전 미리보기가 뜨고, 제출 후 상대 화면에 사진이 보인다
- [ ] **4-b 안내 문구** — 제출 폼에 `지금 제출한 시각이 승부 기준이 돼요...`가 보인다
- [ ] **4-c 빈 증거 제출 불가** — 사진도 없고 텍스트도 비면 제출 버튼 비활성
- [ ] **4-d 오프라인 제출 실패** — 비행기 모드에서 제출
      → **기대**: `증거 제출에 실패했습니다...` 스낵바. 상태가 `판정중`으로 넘어가지 않는다

## 5. 품질전 판정

- [ ] **Q0 사진 필수** — 품질전 대결을 만들어 매칭한 뒤 증거 폼 확인
      → **기대**: `품질전은 사진 증거가 필수예요.` 안내가 뜨고 **텍스트 입력란이 아예 없다**.
      사진을 고르기 전에는 제출 버튼이 비활성
- [ ] **Q1 둘 다 승인** — A 사진 제출 → B 사진 제출 → 서로 `승인`
      → **기대**: 상태 `종료`, 양쪽 다 `모두 승인되어 대결이 종료됐어요.`
      **승/패 문구가 뜨면 안 된다**(품질전은 승자가 없다)
- [ ] **Q2 한쪽 이의제기 즉시 미결** — 새 품질전에서 A 제출 → B 제출 → A가 `이의제기`
      → **기대**: 확인 다이얼로그 문구가 `이의제기하면 이 대결은 미결로 끝나요.`이고,
      진행하면 **B의 판정을 기다리지 않고 즉시** 상태가 `미결`.
      B 화면에서는 승인/이의제기 버튼이 사라지고 `이의제기가 있어 아직 미결 상태예요.`
- [ ] **Q3 사진 표시** — 상대 증거 사진이 상세 화면에 실제로 보인다
      (서명 URL 발급 실패 시 `사진을 불러오지 못했어요.` + `다시 시도`가 그 자리에만 뜬다)

## 5-1. 포기(기권)

매칭된 대결에서 빠져나가는 유일한 길이다. 포기한 쪽이 진다.

- [ ] **F1 확인 다이얼로그** — 진행 중인 속도전 상세 맨 아래 `대결 포기`
      → **기대**: `포기하면 상대의 승리로 기록돼요. 되돌릴 수 없어요.` 다이얼로그.
      `취소`를 누르면 아무 일도 없다
- [ ] **F2 속도전 기권패** — A가 포기
      → **기대**: A 화면 `아쉽지만 패배했어요. / 내가 기권해서 졌어요.`,
      B 화면(새로고침) `승리했습니다! / 상대가 기권해서 이겼어요.`
      대결이 양쪽 `내 대결` 탭에서 빠지고 전적에 승/패로 남는다
- [ ] **F3 품질전 기권** — 진행 중인 품질전에서 A가 포기
      → **기대**: 다이얼로그 문구가 `포기하면 이 대결은 미결로 끝나요.`이고,
      끝난 뒤 양쪽 다 `한쪽이 기권해서 미결로 끝났어요.` 전적에는 `미결`로 남는다
      (품질전은 승자를 두지 않는다)
- [ ] **F4 끝난 대결에는 포기 버튼이 없다** — 종료·미결 대결 상세를 열어본다
      → **기대**: `대결 포기` 버튼이 보이지 않는다
- [ ] **F5 모집 중에는 포기가 아니라 취소** — 아직 매칭 안 된 내 모집
      → **기대**: `대결 찾기` 탭의 `내가 등록한 모집`에서 `취소`로 없앤다

## 6. 목록·화면 동기화

- [ ] **6-1 목록 새로고침** — 상대가 뭔가 한 뒤 `내 대결` 탭을 당겨 새로고침
      → **기대**: 상태 라벨(`진행중`/`판정중`)이 최신으로 갱신
- [ ] **6-1a 탭 복귀 갱신** — 다른 탭에 갔다가 `내 대결` 탭으로 돌아온다
      → **기대**: 당겨 새로고침하지 않아도 목록이 갱신된다(알림이 없어 이 시점에만 다시 읽는다)
- [ ] **6-2 상세 새로고침** — 대결 상세를 당겨 새로고침 → **기대**: 상대의 제출·판정이 반영
- [ ] **6-3 끝난 대결은 `내 대결` 탭에서 빠진다** → **기대**: 판정이 확정되는 순간 `종료`/`미결` 대결은
      `내 대결`에서 사라지고 프로필 전적에서만 보인다. `내 대결`에는 `진행중`/`판정중`만 남는다.
      목록이 비면 `지난 대결은 프로필에서 볼 수 있어요.` 안내와 `대결 찾기` 버튼이 뜨고,
      그 버튼을 누르면 `대결 찾기` 탭으로 넘어간다
- [ ] **6-3a 지난 대결 다시 보기** — 프로필 전적에서 끝난 대결 항목을 탭
      → **기대**: 대결 상세가 열리고 양쪽 증거와 제출 시각, 결과 배너가 그대로 보인다
- [ ] **6-3b 빈 목록에서 새로고침** — 대결이 하나도 없는 상태에서 `내 대결`을 당겨 새로고침
      → **기대**: 새로고침이 동작한다(예전에는 빈 목록에서 아예 먹지 않았다)
- [ ] **6-4 대결 찾기 정리** — 매칭된 대결은 `대결 찾기`의 두 목록에서 모두 사라진다

## 7. 전적·프로필

4·5번을 마친 뒤 A 계정 프로필에서 확인한다.

- [ ] **7-1 집계 줄** — `속도전 N승 M패 · 품질전 K종료 L미결`
      → **기대**: 위에서 끝낸 판수와 정확히 맞는다. S3(양쪽 이의제기)은 승도 패도 아니다
- [ ] **7-2 개별 기록** — 각 줄에 제목, 상대 이름, 유형, 결과 라벨(`승`/`패`/`종료`/`미결`)
- [ ] **7-3 진행 중인 대결은 안 뜬다** — `진행중`/`판정중` 대결은 전적에 없다
- [ ] **7-4 갱신** — 대결을 하나 더 끝낸 뒤 프로필을 다시 열면 즉시 반영
- [ ] **7-5 상대 시점** — B 프로필에서 승/패가 A와 반대로 기록됐는지

## 8. 계정 삭제(탈퇴)

**이 절은 B 계정을 실제로 지운다.** 마지막에 하고, A 계정으로는 하지 않는다.
탈퇴 전에 **끝나지 않은 대결 하나**(`진행중` 또는 `판정중`)와 **사진 증거 하나**를 B가 가진 상태로 만든다.

- [ ] **8-1 확인 다이얼로그** — B: `프로필` 탭 → 맨 아래 `계정` → `계정 삭제`
      → **기대**: 삭제 항목과 대결 처리 방식이 적힌 다이얼로그. `취소`를 누르면 아무 일도 없다
- [ ] **8-2 삭제 실행** — `삭제하기`
      → **기대**: 로그인 화면으로 돌아가고 `계정을 삭제했습니다.` 스낵바
- [ ] **8-3 진행 중이던 대결** — A의 `내 대결` 탭을 새로고침
      → **기대**: B와 하던 미완 대결이 `내 대결`에서 사라진다(승자 없이 `cancelled`)
- [ ] **8-4 묘비** — A 프로필의 지난 전적
      → **기대**: 이미 끝난 대결이 그대로 남아 있고 상대 이름이 `탈퇴한 사용자`.
      **전적이 통째로 사라지면 심각한 버그다**
- [ ] **8-5 증거 사진 삭제** — Supabase 대시보드 → Storage → `battle_evidence` 버킷
      → **기대**: B의 user id 폴더가 비어 있다(사진 삭제는 앱이 Storage API로 하는 부분이라
      실기기에서 실제로 돌려봐야 확인된다)
- [ ] **8-6 재가입** — B 기기에서 같은 구글 계정으로 다시 로그인
      → **기대**: 로그인은 되고, **새 계정**이라 할 일도 전적도 비어 있다

## 9. 테스트 데이터 정리

남겨두면 실제 사용자의 `대결 찾기` 목록에 테스트 대결이 뜬다. A 계정으로 만든 것을 지운다.

1. A의 user id 확인: Supabase 대시보드 → Authentication → Users
2. 임시 SQL 파일을 만들어 실행 (`<A-UUID>` 자리를 채운다)

```sql
delete from public.battles
where creator_id = '<A-UUID>' or opponent_id = '<A-UUID>';

delete from public.todos where user_id = '<A-UUID>';
```

```bash
supabase db query --linked -f <임시파일>.sql
```

3. Storage → `battle_evidence` 버킷에서 남은 테스트 폴더 삭제
4. 프로필까지 지우고 싶으면 A 계정도 앱에서 탈퇴(8번 절차)한다
