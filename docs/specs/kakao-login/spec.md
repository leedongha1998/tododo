# kakao-login 기획

> 작성 2026-11-25 (pm). 오너 요청: "카카오 로그인도 하고 싶다".
> 상태: **초안 — "## 결정 필요"에 오너 답이 필요한 항목이 있다.**

## 배경 (다음 단계가 이 문서만 읽고 일할 수 있도록)

### 이 앱이 무엇인가
투두두두는 친구·모르는 사람과 같은 투두를 걸고 사진 증거로 대결하는 경쟁형 투두 앱이다(Android 전용,
Flutter + Supabase). 1인 개발이고 Google Play 배포가 1차 목표다. 카카오 로그인은 CLAUDE.md "현재 단계"의
**배포 전 별도 feature** 목록에 들어 있다.

### 이미 확정된 전제 (선택지로 다시 열지 않는다)
- 로그인 수단은 **Google + 카카오 두 가지**다(`docs/specs/ai-judge/decisions.md` 26번, 2026-09-14).
  이유는 "카카오톡 접근성을 포기하지 않기 위해서"다.
- **계정 연결은 하지 않는다**(같은 문서 29번). 한 번 가입한 수단으로만 로그인하고, Google과 카카오로 각각
  가입하면 **별개 계정**이다.
- **카카오 친구 목록 API는 MVP에서 쓰지 않는다**(28번). 친구 기능(`friends`)은 배포 후로 미뤘다
  (2026-11-20). 카카오톡 공유 API도 `friends`의 몫이므로 이 기능에서 쓰지 않는다.
- Android만. iOS는 고려하지 않는다.
- `docs/specs/ai-judge/spec.md`의 범위 정의: "`kakao-login` — 카카오 로그인 추가(결정 26, 29). 그에 따른
  개인정보처리방침의 카카오 수집 항목·위탁 표 갱신 포함."

### 지금 로그인과 가입이 어떻게 동작하는가 (사실 확인 결과)
- 로그인 화면에는 **"구글로 로그인" 버튼 하나**만 있다. 앱 밖 브라우저로 Google 로그인을 거쳐 앱으로
  돌아오는 방식이고, 브라우저에 로그인된 계정이 있어도 **항상 계정 선택 화면을 띄운다**(여러 계정을 쓰는
  사용자를 위해).
- 이 방식이라 **앱 서명 지문(SHA-1)을 어디에도 등록하지 않는다**. Play가 앱을 재서명해도 로그인이
  깨지지 않는다(`DEPLOY.md` 1번 참고). 카카오에서도 이 성질이 유지되는지는 아래 "오너 설정"에서 확인 필요로
  남긴다.
- **가입하는 순간 프로필의 표시 이름이 자동으로 정해진다** — Google이 준 이름(실명)이 있으면 그것,
  **없으면 이메일 주소**다. 표시 이름은 비어 있을 수 없다. 즉 **이름도 이메일도 없이 가입하면 가입 자체가
  실패하는 구조**다. 카카오는 이메일을 기본으로 주지 않을 수 있으므로 이 기능의 첫 번째 위험이다.
- 앱 화면 어디에도 이메일을 쓰거나 보여 주는 곳은 없다(표시 이름의 대체값으로만 쓰인다).
- 앱에 **이름을 바꾸는 화면이 없다**. 2026-11-24 보안 점검이 "표시 이름 기본값이 Google 실명, 없으면
  이메일이고, 로그인한 누구나 읽을 수 있으며 모집 목록에 나온다 — 기본 이름을 어떻게 정할지 오너 결정이
  필요하다"를 `TODO_BACKLOG.md`에 남겼다(Google 쪽 문제, 아직 미결).
- 탈퇴는 계정을 실제로 지우되 프로필은 "탈퇴한 사용자" 묘비로 남긴다(상대의 대결 전적 보존). 탈퇴 시
  끝나지 않은 대결은 `cancelled`, 증거 사진은 서버가 지운다. **지금 탈퇴는 외부 로그인 제공자(Google)에
  아무것도 알리지 않는다.**
- 같은 기기에서 로그아웃 후 다른 계정으로 로그인하면 **이전 계정의 할 일 목록이 화면에 남아 보이는 알려진
  문제**가 있다(`TODO_BACKLOG.md`, 2026-11-10 발견, 미수정). 지금까지는 "Google 계정을 여러 개 쓰는
  사람"에게만 드러났지만, 카카오가 생기면 **"구글로 가입한 사람이 카카오로도 눌러 보는" 흔한 경로**에서
  드러난다.

### 정책 문서의 현재 상태
- 개인정보처리방침(`privacy.html`)과 계정 삭제 안내(`account-deletion.html`)는 별도 저장소
  `C:\workspaces\todododo-legal`에 **작성은 끝났고 아직 게시 전**이다(`DEPLOY.md` 0번).
- 방침의 수집 항목은 "Google 계정 이메일·이름", 위탁은 "Supabase/Google"이다. 카카오 항목이 없다.
- 계정 삭제 안내에는 **이메일로 삭제를 요청하는 양식**이 있다.
- Play Console 데이터 보안 양식(아직 미제출)의 수집 항목은 "이메일 주소, 이름, 사용자 생성 콘텐츠, 사진"이다.
- 앱 안의 **AI 데이터 제공 동의 고지**(Google LLC로 대결 제목·기준·증거 사진 제공)는 로그인 수단과 무관하다.

## 목적
카카오톡을 주로 쓰는 한국 사용자가 **Google 계정 없이도, 혹은 Google 계정을 꺼내기 싫어도** 한 번에
가입해 대결 루프에 들어올 수 있게 한다. 메우는 빈자리는 "로그인 화면에서 구글 버튼 하나만 보고 돌아서는
사용자"다 — 출시 직후 사용자 한 명 한 명이 귀한 시점에 가입 문턱 하나를 낮춘다.

부수 효과로, 카카오 가입자는 **실명·이메일이 아닌 카카오 닉네임**을 표시 이름으로 갖게 해 Google 쪽에
남아 있는 "실명/이메일이 모집 목록에 노출"되는 문제를 카카오 경로에서는 처음부터 만들지 않는다.

## 사용자 스토리
1. **카카오톡만 쓰는 신규 사용자**로서, 로그인 화면에서 "카카오로 로그인"을 눌러 몇 번의 탭으로 가입하고
   싶다. 왜냐하면 Google 계정 비밀번호를 기억하지 못하거나 쓰고 싶지 않기 때문이다.
2. **카카오로 가입한 사용자**로서, 대결 상대와 모집 목록에 내 **카카오 닉네임**이 보이고 내 이메일·실명은
   보이지 않기를 바란다. 왜냐하면 모르는 사람과 대결하는 앱이기 때문이다.
3. **카카오로 가입하려는 사용자**로서, 카카오 동의 화면에서 이 앱이 **꼭 필요한 것만** 요구하기를 바란다.
   왜냐하면 친구 목록·전화번호 같은 것을 달라고 하면 가입을 그만두기 때문이다.
4. **Google로 이미 가입한 사용자**로서, 실수로 카카오 버튼을 눌러 빈 새 계정에 들어갔을 때 **그게 다른
   계정이라는 것을 알아차리고** 원래 계정으로 돌아갈 수 있기를 바란다. 왜냐하면 내 할 일과 전적이 사라진
   줄 알고 놀라기 때문이다.
5. **같은 기기에서 계정을 바꿔 로그인하는 사용자**로서, 방금 로그아웃한 계정의 할 일이 새 계정 화면에
   보이지 않기를 바란다.
6. **카카오로 가입했다가 탈퇴하는 사용자**로서, 탈퇴하면 이 앱과 내 카카오 계정의 연결도 정리되기를
   바란다. 왜냐하면 카카오 설정의 "연결된 서비스"에 탈퇴한 앱이 계속 남아 있으면 탈퇴가 덜 된 것처럼
   보이기 때문이다.
7. **오너(운영자)**로서, 카카오 로그인을 붙이는 데 **사업자 등록이나 장기 심사가 필요 없는 범위**에서
   끝내고 싶다. 왜냐하면 2주 MVP 일정이고 1인 개발이기 때문이다.

## 합격선 (위반하면 반려)
1. **카카오 계정으로 이메일을 주지 않고도 가입이 성공한다.** 이메일이 없어서 가입이 실패하는 경로가
   하나라도 남으면 불합격이다.
2. **카카오 가입자의 표시 이름에 이메일이 들어가지 않는다.** 닉네임이 어떤 이유로 비어 있어도 이메일·
   빈 문자열·식별 번호가 표시 이름이 되지 않는다.
3. **카카오에 요청하는 동의항목에 친구 목록·카카오톡 메시지·전화번호·실명·생일·성별·연령대가 없다.**
4. **Google 로그인의 동작이 한 글자도 바뀌지 않는다**(항상 계정 선택, 표시 이름 규칙 포함).
5. **Google 계정과 카카오 계정이 어떤 조건에서도 하나의 계정으로 합쳐지지 않는다**(결정 29). 같은 이메일을
   가진 경우도 포함한다.
6. **Play에서 내려받은 릴리스 빌드(내부 테스트 트랙)로 카카오 로그인이 된다.** 디버그 빌드에서만 되는 것은
   합격이 아니다(Play 재서명 때문에 둘이 다를 수 있다).
7. 개인정보처리방침이 **카카오 로그인 출시 전에** 카카오 수집 항목을 반영한다.

## 범위 안

### P0-1. 로그인 화면에 카카오 로그인 추가
- 로그인 화면에 "구글로 로그인"과 나란히 **"카카오로 로그인"**을 둔다. 순서·모양은 디자이너가 정하되,
  카카오가 정한 로그인 버튼 디자인 가이드가 있으면 그것을 따른다(가이드 준수 의무 여부는 design 단계에서
  확인).
- 카카오 로그인으로 **처음 들어오면 새 계정이 생기고**, 같은 카카오 계정으로 다시 들어오면 **그 계정으로
  로그인**된다.
- 사용자가 카카오 화면에서 취소하거나 동의를 거부하면 **로그인 화면으로 돌아오고** 앱이 빈 화면·로딩에
  갇히지 않는다. 취소는 실패가 아니므로 실패 토스트를 띄울지 말지는 디자이너가 정한다. 실제 오류(네트워크
  등)는 기존 Google과 같이 토스트로 알린다.
- 로그인 화면에 **"구글과 카카오 계정은 서로 연결되지 않아요. 처음 가입한 방법으로 로그인해 주세요."**
  취지의 한 줄을 둔다(사용자 스토리 4). 정확한 문구는 디자이너.

### P0-2. 카카오 동의항목 — 닉네임 하나만 받는다
| 항목 | 받는가 | 이유 |
|---|---|---|
| 닉네임 | **받는다 (필수 동의)** | 표시 이름. 앱이 사람을 구분해 보여 주는 유일한 값이다 |
| 프로필 사진 | 받지 않는다 | 앱에 프로필 사진을 보여 주는 화면이 없다. 안 쓰는 것을 받으면 방침에 적을 항목만 늘어난다 |
| 카카오계정(이메일) | **받지 않는다 (추천, "결정 필요" 1)** | 앱이 이메일을 쓰는 곳이 없다. 받지 않으면 계정 자동 합침(합격선 5)과 이메일 노출(합격선 2) 위험이 원천적으로 사라진다 |
| 이름·성별·연령대·생일·전화번호·배송지 등 | 받지 않는다 | 쓰는 곳이 없다. 대부분 검수·비즈 앱이 필요하다 |
| 카카오톡 친구 목록·메시지 전송 | 받지 않는다 | 결정 28. `friends`(배포 후)의 몫 |

카카오 회원번호(카카오가 사용자를 구분하는 식별자)는 로그인 자체에 따라오는 값이라 동의항목이 아니지만,
**수집은 되는 것**이므로 방침에 적는다(P0-6).

### P0-3. 카카오 가입자의 표시 이름
- 카카오 가입자의 표시 이름은 **카카오 닉네임**이다.
- 닉네임을 받지 못한 경우(동의 설정 실수, 카카오 쪽 공란 등)에도 가입은 성공하고 표시 이름은 **이메일이
  아닌 기본값**이 된다. 기본값의 정확한 꼴은 디자이너가 정하되, "연습 봇"·"탈퇴한 사용자"처럼 **시스템이
  쓰는 이름과 헷갈리지 않아야** 한다.
- 가입 이후 카카오에서 닉네임을 바꿔도 앱의 표시 이름을 따라 바꾸지 않는다(지금 Google도 가입 시 한 번만
  정한다. 같은 규칙).
- **Google 가입자의 기본 이름 규칙(실명, 없으면 이메일)은 이 기능에서 바꾸지 않는다** — `TODO_BACKLOG.md`의
  보안 점검 항목으로 별도 오너 결정이 남아 있다. 이 기능이 그 결정을 대신하지 않는다.

### P0-4. 내가 어느 계정으로 들어와 있는지 보인다
- 프로필 화면에 **이 계정의 로그인 수단(Google/카카오)**이 보인다(사용자 스토리 4). 이메일·카카오 회원번호
  같은 식별값은 보여 주지 않는다 — 수단 이름 하나면 "아, 다른 계정이구나"를 알아차리기에 충분하다.
- 같은 사람이 두 수단으로 각각 가입한 경우, 다른 사용자에게는 **그냥 서로 다른 두 사용자**로 보인다.
  로그인 수단은 **본인 프로필에만** 보이고 상대 전적 카드·모집 목록에는 보이지 않는다(공개할 이유가 없다).

### P0-5. 계정을 바꿔 로그인하면 이전 계정의 데이터가 보이지 않는다
- 로그아웃(또는 탈퇴) 뒤 같은 기기에서 다른 계정으로 로그인하면, 할 일 목록을 비롯해 **화면에 보이는 어떤
  것도 이전 계정의 것이 아니다**.
- 이것은 `TODO_BACKLOG.md`에 이미 있는 버그(로그인·로그아웃 때 할 일 목록 캐시를 비우지 않음)이지만,
  카카오가 생기면 "구글 사용자가 카카오 버튼을 눌러 보는" 흔한 경로에서 **남의 계정(실제로는 자기의 다른
  계정) 데이터가 보이는 것처럼** 드러나므로 이 기능의 P0로 끌어온다.

### P0-6. 개인정보처리방침·계정 삭제 안내·Play 데이터 보안 갱신
갱신하는 자리와 내용(법적 고지라 **최종 문구는 오너 승인 사항**이다):

1. **`privacy.html`** (별도 저장소 `todododo-legal`)
   - 수집 항목에 "카카오 로그인 시: 카카오 회원번호, 닉네임"을 추가한다(이메일을 받기로 하면 이메일도).
     기존 "Google 계정 이메일·이름"은 "Google 로그인 시"로 갈라 적는다.
   - 수집 방법(경로)에 "카카오 로그인 과정에서 카카오로부터 제공받음"을 추가한다.
   - 탈퇴 시 처리 표에 카카오 연결 끊기 여부를 적는다("결정 필요" 2의 답에 따라).
   - 카카오(주식회사 카카오)의 지위 — **위탁 표에 올릴지, 수집 출처로만 적을지** — 는 확인 필요다.
     `decisions.md`는 "위탁 표(Kakao Corp.) 갱신"이라 적었지만, 소셜 로그인 제공자는 이 앱의 일을 대신
     처리하는 수탁자라기보다 정보를 넘겨주는 쪽이라 위탁이 맞는지 법적 판단이 필요하다("결정 필요" 4).
   - 시행일을 갱신한다.
2. **`account-deletion.html`**
   - 삭제/보존 표에 카카오 연결 끊기 여부를 추가한다.
   - **이메일 요청 양식이 카카오 가입자에게는 작동하지 않는다** — 이메일을 받지 않으면 운영자가 요청자의
     계정을 찾을 방법이 없다. 카카오 가입자에게는 "앱에서 카카오로 로그인 → 프로필 → 계정 삭제"를 1순위로
     안내하고, 앱을 쓸 수 없는 경우의 대안(예: 표시 이름과 가입 시기를 적어 요청)을 적는다. 대안의 꼴은
     오너가 정한다("결정 필요" 4에 포함).
3. **Play Console 데이터 보안 양식**(`DEPLOY.md` 5번): "이름" 항목의 설명에 카카오 닉네임을, "사용자 ID"
   성격의 항목에 카카오 회원번호를 반영할지 확인한다. 이메일은 Google 가입자에게서만 수집된다.
4. **`DEPLOY.md`**: 5번의 "이 앱이 수집하는 것" 한 줄과 7번 최종 확인에 "릴리스 빌드 실기기 카카오 로그인·
   탈퇴" 줄을 추가한다(메인 세션 몫).
5. **AI 데이터 제공 동의 고지는 바꾸지 않는다** — 카카오에서 받은 어떤 값도 Google(Gemini)로 나가지 않는다.
   이 사실이 유지되는 것 자체가 수용 기준이다.

### P0-7. 탈퇴 시 카카오 연결 정리
- 카카오 가입자가 탈퇴하면 기존 탈퇴 흐름(묘비, 대결 `cancelled`, 사진 삭제)이 **그대로** 돌고, 그에 더해
  **이 앱과 그 카카오 계정의 연결을 끊는다**("결정 필요" 2, 추천은 P0로 포함).
- 연결 끊기가 실패해도 **탈퇴 자체는 되돌리지 않는다**(이미 데이터를 지운 뒤다). 실패를 사용자에게 어떻게
  알릴지는 디자이너가 정하되, 운영자가 알 수 있게 기록은 남긴다.
- 탈퇴한 카카오 계정으로 다시 로그인하면 **완전히 새 계정**이 된다(이전 할 일·점수·전적은 돌아오지 않는다).
  Google의 지금 동작과 같다.

## 오너가 직접 해야 할 설정
아래는 계정 소유자만 할 수 있는 콘솔 작업이다. **[확인 필요]로 표시한 것은 이 문서 작성 시점에 사실을
확인하지 못한 것**이고, design/developer 단계에서 카카오·Supabase 공식 문서로 확인한 뒤 확정한다.
추측으로 단정하지 않는다.

### 카카오 개발자 콘솔 (developers.kakao.com)
1. 애플리케이션 생성(앱 이름 `투두두두`, 아이콘). 개인 개발자 계정으로 만들 수 있는지 [확인 필요].
2. **카카오 로그인 활성화.**
3. **Redirect URI 등록** — Supabase가 카카오로부터 결과를 받는 주소(Supabase 프로젝트의 auth 콜백 주소 꼴로
   알려져 있다)를 등록한다. 정확한 값은 Supabase 대시보드의 카카오 공급자 설정 화면에 표시되는 값을 그대로
   쓴다 [확인 필요]. 앱으로 돌아오는 주소(`com.todododo.todododo://login-callback/`)는 카카오가 아니라
   Supabase 쪽에 등록하는 것으로 보인다 [확인 필요].
4. **플랫폼 등록(Android: 패키지명 `com.todododo.todododo`, 키 해시)** — 지금 Google처럼 브라우저를 거치는
   방식이면 키 해시가 **필요 없을 수 있고**, 카카오톡 앱을 직접 여는 방식이면 **필요하다** [확인 필요].
   필요하다면 **디버그 키, 업로드 키, Play 앱 서명 키 세 개의 해시를 모두** 등록해야 한다 — Play가 앱을
   재서명하므로 업로드 키만 등록하면 Play에서 받은 앱만 로그인이 깨진다(합격선 6).
5. **동의항목 설정** — 닉네임 "필수 동의", 그 외 전부 "사용 안 함"(P0-2). 이메일을 받기로 하면 그때 필요한
   권한·심사·비즈 앱 여부 [확인 필요].
6. **보안 → Client Secret** 생성·활성화 여부와, Supabase에 넣을 키가 어느 키(REST API 키 등)인지 [확인 필요].
7. 앱 정보에 개인정보처리방침 URL 등록이 요구되는지 [확인 필요] — 요구된다면 `todododo-legal` 게시
   (`DEPLOY.md` 0번)가 이 기능의 선행 조건이 된다.
8. 비즈 앱이 아닌 상태에서 카카오 로그인 사용에 인원·기능 제한이 있는지 [확인 필요].

### Supabase 대시보드
1. **Authentication → Providers → Kakao** 활성화, 카카오 콘솔의 키·Client Secret 입력.
2. **이메일 없는 카카오 사용자 허용** 설정이 있는지, 기본값이 무엇인지 [확인 필요]. 이 설정이 없거나 꺼져
   있으면 이메일을 받지 않는 카카오 사용자의 가입이 Supabase 단계에서 막힐 수 있다 — 합격선 1과 직결.
3. Supabase가 카카오에 **기본으로 이메일을 함께 요청하는지** [확인 필요]. 그렇다면 카카오 콘솔에서 이메일을
   설정하지 않았을 때 카카오가 오류를 낼 수 있다 — 이 경우 요청 항목을 좁히는 방법이 있는지 developer 단계에서
   확인한다.
4. **같은 이메일 계정 자동 합침**(Supabase의 자동 계정 연결) 동작 [확인 필요]. 이메일을 받지 않으면 이
   문제는 생기지 않는다. 받기로 하면 합격선 5를 지키기 위한 조치가 필요하다.
5. **Redirect URLs**에 `com.todododo.todododo://login-callback/`이 이미 들어 있어야 한다(`DEPLOY.md` 7번,
   Google용으로 이미 필요). 카카오도 같은 주소를 쓰는지 [확인 필요].

## 수용 기준

### 가입·로그인
- [ ] 로그인 화면에 Google과 카카오 두 버튼이 있고, 계정이 서로 연결되지 않는다는 안내 한 줄이 있다.
- [ ] 카카오 계정으로 처음 로그인하면 새 계정이 생기고 메인 화면으로 들어간다.
- [ ] 로그아웃 후 같은 카카오 계정으로 다시 로그인하면 **같은 계정**(같은 할 일·점수·전적)으로 들어간다.
- [ ] 카카오 동의 화면에 **닉네임 외의 항목이 없다**(이메일을 받기로 결정한 경우에만 이메일 추가).
- [ ] 카카오 화면에서 취소·동의 거부하면 로그인 화면으로 돌아오고 앱이 갇히지 않는다.
- [ ] 네트워크 오류 등 실제 실패는 토스트로 알린다(에러를 삼키지 않는다).
- [ ] Google 로그인은 이전과 똑같이 동작한다(항상 계정 선택, 기존 계정으로 로그인).

### 표시 이름
- [ ] 카카오 가입자의 표시 이름이 카카오 닉네임이다. 모집 목록·대결 상대 카드에도 그 이름이 보인다.
- [ ] 닉네임이 없는 경우를 재현했을 때(콘솔 설정 등) 가입이 실패하지 않고, 표시 이름이 이메일·공란·숫자
      식별자가 아닌 기본값이다. 그 기본값이 "연습 봇"·"탈퇴한 사용자"와 헷갈리지 않는다.
- [ ] 이메일을 주지 않은 카카오 계정으로 가입이 성공한다(합격선 1).

### 두 계정
- [ ] 같은 사람이 Google과 카카오로 각각 가입하면 서로 다른 두 계정이고, 어느 쪽 데이터도 다른 쪽에 보이지
      않는다. 같은 이메일이어도 합쳐지지 않는다(이메일을 받는 경우에만 시험 가능).
- [ ] 본인 프로필에 로그인 수단(Google/카카오)이 보인다. 다른 사람의 카드·모집 목록에는 보이지 않는다.
- [ ] Google 계정으로 로그인해 할 일을 본 뒤 로그아웃하고 **앱을 끄지 않은 채** 카카오로 로그인하면,
      이전 계정의 할 일이 한 순간도 보이지 않는다(반대 방향도).

### 탈퇴
- [ ] 카카오 가입자가 탈퇴하면 기존 탈퇴와 똑같이 묘비·대결 `cancelled`·사진 삭제가 일어난다.
- [ ] ("결정 필요" 2에서 포함하기로 한 경우) 탈퇴 후 카카오 계정 설정의 연결된 서비스 목록에서 투두두두가
      사라진다. 연결 끊기가 실패해도 탈퇴는 완료되고, 운영자가 실패를 알 수 있는 기록이 남는다.
- [ ] 탈퇴한 카카오 계정으로 다시 로그인하면 빈 새 계정이 된다.

### 고지·문서
- [ ] `privacy.html`에 카카오 로그인 시 수집 항목(회원번호, 닉네임[, 이메일])과 수집 경로가 있고 시행일이
      갱신됐다. 카카오의 지위(위탁/수집 출처)가 "결정 필요" 4의 답대로 적혀 있다.
- [ ] `account-deletion.html`에 카카오 가입자의 삭제 경로가 있다.
- [ ] AI 데이터 제공 동의 고지 문구는 바뀌지 않았고, 카카오에서 받은 값이 AI 요청에 들어가지 않는다.
- [ ] Play 데이터 보안 양식 초안(`DEPLOY.md` 5번)이 카카오 수집 항목과 어긋나지 않는다.

### 빌드·테스트
- [ ] Play 내부 테스트 트랙에서 받은 **릴리스 빌드**로 실기기에서 카카오 가입·재로그인·탈퇴가 된다(합격선 6).
      카카오톡이 설치된 기기와 설치되지 않은 기기 양쪽에서 확인한다.
- [ ] 새 패키지를 들였다면 릴리스 빌드(`flutter build apk --release ...`)가 통과한다(CLAUDE.md 개발 환경 규칙).

## 트레이드오프
- **이메일을 받지 않는다(추천안)** → 얻는 것: 비즈 앱·심사 없이 출시, 동의 화면이 가벼워 가입 이탈 감소,
  계정 자동 합침·이메일 노출 위험 원천 차단, 방침에 적을 항목 축소. 잃는 것: **운영자가 카카오 가입자에게
  연락할 수단이 없고**, 앱 밖(웹)에서 들어온 삭제 요청의 본인 확인이 어렵다. 나중에 계정 연결(배포 후 필요해질
  경우)을 이메일로 할 수 없다.
- **카카오 닉네임을 표시 이름으로 쓴다** → 실명 노출이 없지만, 닉네임이 겹치거나 엉뚱한 값일 수 있다. 이름
  바꾸기 화면이 없으므로 사용자가 고칠 방법이 없다(Google 쪽과 같은 한계, 별도 결정 대상).
- **계정 연결 없음(전제)** → 같은 사람이 두 계정을 갖고 데이터가 갈라진다. 이 기능은 그 혼란을 **안내 한 줄과
  프로필의 수단 표시로만** 완화하고, 합치는 수단은 주지 않는다. 실수로 만든 빈 계정은 사용자가 직접 탈퇴해야
  정리된다.
- **자기 자신과의 대결을 막지 않는다** → Google+카카오 두 계정으로 자기 모집에 자기가 참가해 한쪽 점수를 올릴
  수 있다. 그러나 이미 Google 계정 여러 개로 가능한 일이고, 랭킹이 없어 점수를 부풀려도 남에게 보일 자리가
  프로필과 상대 카드뿐이다. 막으려면 기기·본인 식별이 필요해 범위가 크게 늘어난다.
- **계정 전환 시 데이터 잔상 버그를 이 기능에 끌어온다(P0-5)** → 기능 범위가 조금 늘지만, 빼면 카카오
  출시가 곧 "남의 데이터가 보이는 듯한" 첫인상을 만든다.
- **탈퇴 시 연결 끊기를 P0로 넣는 경우** → 서버가 카카오와 통신하는 일이 하나 늘고, 그 실패가 탈퇴와 별도로
  남는 상태(앱 계정은 지워졌는데 카카오 연결은 남음)를 받아들여야 한다. 빼는 경우 → 구현은 가볍지만 카카오
  설정에 탈퇴한 앱이 남고, 카카오 정책상 요구라면 검수·운영 리스크가 된다.
- **카카오 연결 끊기 알림(카카오 쪽에서 끊은 경우) 처리를 하지 않는다** → 카카오 설정에서 연결만 끊은 사용자의
  앱 계정이 남는다. 이 경우는 탈퇴가 아니므로 계정을 지우지 않는 것이 오히려 안전하다고 보고 미룬다.
